# Архитектура «Байта»

Документ описывает, как устроен код. Что и зачем делает продукт — в `DESIGN-DOC.md`;
почему выбрано именно так — в `DECISIONS.md`.

## Компоненты

```
Telegram ──initData──▶ client (React, Mini App / веб) ──JWT──▶ Caddy ─▶ api (FastAPI)
                         │ Pyodide в Web Worker                   │
                         │ (vendored, без CDN)                    ├─ PostgreSQL 16
                                                                  ├─ Redis 7 ── ARQ ──▶ worker
Telegram Bot API ◀── bot (aiogram 3, webhook) ── /api/internal ───┤               └─▶ runner (nsjail)
                 ◀── worker (рассылки уведомлений)                 ├─ runner (nsjail, сеть sandbox)
                                                                  └─ MinIO/S3 (ассеты экземпляров)
```

| Каталог | Роль | Ключевые модули |
|---|---|---|
| `egegen/` | 27 процедурных генераторов, решатели, чекеры | `core/generator.py` (контракт), `generators/tNN.py`, `checkers/`, `config/templates/*.yaml`, `config/cards/*.md`, `config/fipi_2027.yaml`, `pymin.py` |
| `api/` | Вся бизнес‑логика и HTTP | `app/logic/*` (чистые правила), `app/services/*` (правила + БД), `app/api/*` (роутеры), `app/db/models.py`, `app/config/*.yaml` |
| `worker/` | Периодика и фоновые задачи | `bayt_worker/main.py` → `app/services/scheduler.py` |
| `bot/` | Вход в Mini App, приглашения кураторов, ссылки в веб | `bayt_bot/main.py`, `texts.py`, `throttle.py` |
| `runner/` | Запуск кода учеников | `bayt_runner/sandbox.py` (nsjail), `server.py` (HTTP на stdlib) |
| `client/` | Mini App и веб‑версия | `src/App.tsx`, `src/screens/*`, `src/lib/{api,tg,python,pyworker,sheet,markdown}.ts` |
| `infra/` | Caddy, деплой, бэкапы | `Caddyfile`, `deploy-stage.sh`, `scripts/backup-loop.sh` |

## Слои API

1. **`app/logic`** — чистые функции без ввода‑вывода: награды и кэп (`rewards`), серия
   (`streak`), Elo‑модель навыка, уверенность и прогноз (`skills`), планировщик
   дейликов (`planner`), правила уведомлений (`notify`), экзамен, куратор, стартовый
   тест. Покрыты юнит‑тестами и симуляцией экономики трёх профилей (5.4).
2. **`app/services`** — сценарии поверх БД: ответ на задачу (`answers`), действия на
   экране задачи (`tasks`), этажи/экстерн/босс (`floors`), магазин, экзамены,
   кураторы, уведомления, тикеты, приватность, админка, планировщик воркера.
3. **`app/api`** — тонкие роутеры: валидация (Pydantic), авторизация, лимиты,
   идемпотентность (`Idempotency-Key` → Redis, 24 ч).

Все числа экономики — в `app/config/economy.yaml` (с `season_id`), этажи —
`floors.yaml`, задания и шкала баллов — `curriculum.yaml`. Конфиги валидируются при
старте; админка может переопределить их без деплоя (таблица `config_overrides`),
цены — только вместе со сменой `season_id` (5.6).

## Жизненный цикл экземпляра (12.4)

`planned → issued → attempted → solved | failed | revealed → expired`

* Экземпляр создаётся из `seed = derive_seed(user, day, task, attempt, slot)`;
  генерация — чистая функция `(seed, difficulty, subtype)`, поэтому любой файл можно
  пересоздать по seed (`instances.read_asset`).
* В строке экземпляра хранятся эталон, `hidden_seed`, решение и эталонный код; клиенту
  отдаётся проекция `instances.public()` без них (проверено тестом по всем ключам).
* Файл B задания 27 (10⁶ чисел) строит воркер заранее (`build_big_file`).

## Ответ на задачу (`services/answers.submit`)

1. Нормализация и проверка чекером egegen; ошибка формата — не попытка (7.4).
2. Метод‑чек, если ответ быстрее ~11 % нормы (7.5.3).
3. Перепроверка кода для 16, 17, 23–27 на скрытом варианте (7.5.2, решение D‑024):
   программа ученика и эталонный код этого экземпляра запускаются на данных скрытого
   варианта; совпало — «Решено надёжно», иначе половина монет и вес 0,3 в модели.
4. Монеты: базовая ставка × модификаторы, кэп дня, идемпотентная транзакция
   `reward:{instance}`; XP; обновление навыка; порог → серия; вехи → куратору.
5. Хуки закрытия контекста (`on_close`): стартовый тест, экстерн, босс.

## Время и пояса

«День» ученика начинается в 05:00 по его поясу (`logic/timeutil.study_day`). Воркер
запускает задания каждые 5 минут по UTC и для каждого пользователя решает по его
локальному времени: план в 05:00, «дейлики открыты» в выбранное время, 20:00/22:00
напоминания, воскресные итоги. Уведомления: ≤ 2 в день ученику, тихие часы
23:00–08:00, отдельный бюджет куратора (D‑023), дедупликация по уникальному ключу.

## Безопасность

* Вход: HMAC `initData` (≤ 10 мин), Login Widget через redirect (без стороннего
  скрипта), одноразовые ссылки из бота. JWT 15 мин + refresh 30 дней с ротацией и
  отзывом всех сессий при повторном использовании refresh.
* На stage/prod API не стартует с dev‑секретами (`Settings.check_production`).
* Раннер: nsjail, uid 65534 внутри и снаружи, пустое окружение, минимальная ФС только
  для чтения, свой `/work`, лимиты CPU 10 с, 256 МБ, файлы 16 МБ, 32 процесса;
  контейнер раннера — только во внутренней сети `sandbox` без выхода в интернет.
* CSP `default-src 'self'` (Caddy): Pyodide и шрифты — со своего домена.
* Лимиты: 60 ответов/мин, 20 серверных запусков/ч, 240 запросов/мин, 30 входов/мин с IP.
* Аудит админских действий и денежных операций вне игры (`audit_log`).

## Данные

32+ таблицы (`app/db/models.py`), миграции Alembic (`api/alembic`). Все таблицы
пользователя каскадно удаляются вместе с `users` (удаление аккаунта за 7 дней,
`privacy.purge_due`). Ежедневный `pg_dump` (30 дней) и ежемесячная проверка
восстановления (`infra/scripts/restore-check.sh`).

## Клиент

* Роутинг — `react-router`; данные — TanStack Query; сессия — Zustand.
* `lib/tg.ts` оборачивает `@telegram-apps/sdk`: тема, MainButton, BackButton, haptics,
  подтверждение закрытия, CloudStorage для refresh; вне Telegram всё безопасно
  выключается (веб‑версия).
* Python: Pyodide в Web Worker, грузится лениво при первом открытии редактора и
  кэшируется Service Worker; зацикленная программа останавливается через 10 с
  уничтожением воркера. Для слабых устройств — «выполнять на сервере».
* Редактор CodeMirror 6 — отдельный чанк; основной бандл ≈ 115 КБ gzip (бюджет 300 КБ,
  проверяется `scripts/check-size.mjs` в CI).
