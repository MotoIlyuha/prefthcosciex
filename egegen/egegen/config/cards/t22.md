# Задание 22 · Параллельные процессы

### common

**Одна формула решает почти всё.**

> Момент окончания процесса = его длительность + **максимум** моментов
> окончания всех процессов, от которых он зависит.

Процесс стартует после **всех** зависимостей, а не после первой из них —
поэтому именно максимум, а не сумма и не минимум.

```python
import csv
from functools import lru_cache

rows = list(csv.reader(open('22.csv'), delimiter=';'))[1:]
proc = {int(r[0]): (int(r[1]),
        [int(x) for x in r[2].split(';') if x.strip() not in ('', '0')])
        for r in rows}

@lru_cache(None)
def fin(p):
    t, deps = proc[p]
    return t + max((fin(d) for d in deps), default=0)

print(max(fin(p) for p in proc))       # минимальное общее время
```

**Как себя проверить.** Выведите `fin(p)` для двух‑трёх процессов без
зависимостей — должно получиться ровно их время выполнения. Если нет,
неправильно разобран столбец зависимостей.

**Ловушки.**

* Зависимости записаны через `;` — `r[2].split(';')`, а «0» означает
  «зависимостей нет», это не идентификатор процесса.
* Число процессоров не ограничено, **если в условии не сказано иначе**.
* «Через какое время завершится» — это **момент**, а не длительность
  последнего процесса.
* Порядок строк в файле произвольный: рекурсия с кэшем от него не зависит.

### 22.2_max_parallel

Каждый процесс занимает отрезок времени `[fin(p) − t(p); fin(p)]`. Соберите
события «начался» (+1) и «закончился» (−1), отсортируйте и пройдите по ним,
считая текущее число активных процессов и запоминая максимум.

### 22.5_limited_cpus

Процессоров мало, поэтому готовые процессы ждут очереди. Условие всегда
задаёт правило выбора — обычно «первым запускается готовый процесс
с наименьшим идентификатором». Моделируйте по тактам: на каждом такте
уменьшайте остаток у работающих, завершайте те, у кого он дошёл до нуля,
и заполняйте освободившиеся процессоры.
