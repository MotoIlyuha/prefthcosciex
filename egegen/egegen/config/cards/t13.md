### common

**Идея — динамика по числам.** Обозначим `f(a, b)` — количество программ,
переводящих `a` в `b`. Тогда:

* `f(b, b) = 1` — пустая программа тоже считается;
* `f(a, b) = 0` при `a > b` — команды только увеличивают число;
* иначе `f(a, b)` — сумма по всем командам: `f(a+1, b) + f(a*2, b) + …`

```python
from functools import lru_cache
@lru_cache(None)
def f(a, b):
    if a > b: return 0
    if a == b: return 1
    return f(a + 1, b) + f(a * 2, b)     # ← команды из условия

print(f(3, 20))                          # всего программ
print(f(3, 12) * f(12, 20))              # через 12
print(f(3, 20) - f(3, 15) * f(15, 20))   # минуя 15
print(f(3, 12) * (f(12, 20) - f(12, 15) * f(15, 20)))   # через 12, не через 15
```

**Ловушки.**

* Пустая программа считается: `f(x, x) = 1`. Это самая частая потеря балла.
* Две команды могут давать один результат (1 → 2 через «+1» и через «×2») —
  это **разные** программы, и обе считаются.
* «Не через C» вычитанием корректно только потому, что команды монотонно
  увеличивают число: через C можно пройти не более одного раза.
* «Через C и через D» — если C < D, порядок фиксирован, и формула
  `f(A,C) · (f(C,B) − f(C,D)·f(D,B))` даёт «через C, но не через D».

### 13.5_non_monotone

Здесь есть команда, **уменьшающая** число, поэтому значения могут возвращаться
назад и программ становится бесконечно много. Условие всегда добавляет рамки:
диапазон допустимых значений и максимальную длину программы. Считаем с ними:

```python
@lru_cache(None)
def f(a, steps):
    here = 1 if a == B else 0
    if steps == 0: return here
    total = here
    for nxt in (a + 1, a * 2, a - 1):        # ← команды
        if LO <= nxt <= HI: total += f(nxt, steps - 1)
    return total
```

Обратите внимание: попав в B, программа может закончиться **или** продолжиться
и вернуться — поэтому `here` прибавляется, а не возвращается сразу.
