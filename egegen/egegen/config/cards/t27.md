# Задание 27 · Два файла, эффективный алгоритм

### common

> **Изменение 2027 года:** ответ записывается **в одну строку из двух чисел**
> через пробел (раньше — в две строки). Первое число — для файла A, второе —
> для файла B.

**Два файла — это не два задания, а проверка алгоритма.** Файл A маленький:
на нём работает даже перебор двумя циклами. Файл B — миллион чисел: квадратичный
перебор это 10¹² операций, он не успеет никогда.

**Порядок работы — строго такой.**

1. Написать наивное решение (два цикла) и получить ответ для **A**.
2. Написать быстрое решение (один проход) и получить ответ для **A**.
3. **Сравнить.** Совпало — запускать на B. Не совпало — ошибка в быстром
   решении, и файл B считать рано.

**Шаблон: пара на расстоянии ≥ K с суммой, кратной M.**

```python
for name in ("27A.txt", "27B.txt"):
    f = open(name)
    n = int(f.readline())
    a = [int(f.readline()) for _ in range(n)]
    K, M = 5, 7  # ← параметры из условия
    best = None
    mx = [None] * M  # лучший элемент по каждому остатку
    for i in range(n):
        if i - K >= 0:  # элемент стал «достаточно далёким»
            r = a[i - K] % M
            if mx[r] is None or a[i - K] > mx[r]:
                mx[r] = a[i - K]
        need = (-a[i]) % M  # какой остаток нам нужен
        if mx[need] is not None:
            s = a[i] + mx[need]
            if best is None or s > best:
                best = s
    print(best, end=" ")  # 2027: оба ответа в одной строке
```

Идея одной строкой: когда мы стоим на элементе `a[i]`, все элементы с номерами
до `i − K` уже «разрешены», и среди них для каждого остатка достаточно помнить
**один** — самый большой.

**Ловушки.**

* «Расстояние не менее K» — это разность **номеров** ≥ K, а не > K.
* Первая строка файла — количество чисел, а не данные.
* Числа бывают отрицательными: `(-a[i]) % M` в Python даёт правильный
  неотрицательный остаток, это как раз то, что нужно.
* Максимум или минимум — перечитайте вопрос.
* Формат ответа: **одна строка, два числа**.

### 27.4_window_sum

Сумма окна считается «скользяще»: посчитали первую, дальше на каждом шаге
прибавляем вошедший элемент и вычитаем вышедший. Пересчитывать сумму окна
заново — это снова квадратичный алгоритм.

### 27.5_median_point

Суммарное расстояние минимально в **медиане**, а не в среднем. Отсортируйте
координаты и возьмите средний элемент; для чётного количества подойдёт любая
точка между двумя центральными, сумма будет одинаковой.

```python
b = sorted(a)
med = b[len(b) // 2]
print(sum(abs(x - med) for x in b))
```
