# Задание 17 · Обработка числовой последовательности

### common

**Скелет решения всегда один и тот же.**

```python
a = [int(x) for x in open("17.txt")]  # файл в список
cnt = 0
best = -(10**9)  # заведомо меньше любой суммы
for i in range(len(a) - 1):  # пары соседей
    x, y = a[i], a[i + 1]
    if (x % 3 == 0) != (y % 3 == 0) and (x + y) % 5 == 0:  # ← условие
        cnt += 1
        best = max(best, x + y)
print(cnt, best)  # ← количество, затем сумма
```

**Порядок работы.**

1. Если в условии есть «вспомогательная величина» (наименьшее число,
   оканчивающееся на 7; квадрат максимального) — посчитайте её **до** цикла.
2. Напишите условие отдельной строкой.
3. Прогоните программу на первых 10 числах файла и сверьте глазами.

**Ловушки.**

* Числа **отрицательные**: в Python `-7 % 10` равно 3, а не 7. Последнюю цифру
  берите как `abs(x) % 10`.
* «Ровно одно из чисел» — это `!=` между двумя условиями, а не `or`.
* «Сумма пары кратна» и «оба числа кратны» — разные условия.
* «Пара» — это **соседние** элементы, если не сказано иначе.
* Порядок вывода: сначала количество, потом сумма. Перепутали — ноль баллов.
* `best` начинайте с очень маленького числа, а не с нуля: суммы бывают
  отрицательными.

### 17.3_global_value

Вспомогательная величина считается одним проходом **до** основного цикла:

```python
m = max(x for x in a if abs(x) % 10 == 7)  # или min — читайте условие
```

Если подходящих чисел может не быть, `min` бросит исключение — в реальных
КИМ такие числа всегда есть, но на своих тестах учтите это.

### 17.5_distance_k

Индексы `i` и `i + k`, поэтому цикл идёт до `len(a) - k`, а не до `len(a) - 1`.
Самая частая ошибка здесь — потерять последнюю пару или выйти за границу списка.
